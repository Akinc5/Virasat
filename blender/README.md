# Virasat procedural monuments (Blender)

Every 3D monument in Virasat is generated by a Python script that runs inside
Blender. Nothing is hand-modelled or downloaded, so a model can be rebuilt,
reviewed in a diff, and tuned by changing a parameter.

```
blender/
  lib/common.py      scene, collections, materials, geometry generators, UVs, booleans, export
  lib/arch.py        façade frames, pointed and cusped Mughal arches, recesses, mouldings, spandrels
  lib/textures.py    texture cache + base marble / jali / sandstone generators
  lib/motifs.py      inlay motif library (vector-style canvas → tileable textures), khondalite + relief
  lib/presentation.py shared studio turntable, sky lighting, cameras, render loop
  monuments/*.py     one script per monument → public/models/<name>.glb
  preview.py         quick render of any exported GLB
  build.mjs          runs every monument script (npm run models)
  out/               build outputs: .blend files, textures, renders, v1/ archive (git-ignored)
```

## Requirements

- Blender **4.5 LTS**. `build.mjs` looks in `C:\Program Files\Blender Foundation`,
  then on `PATH`, then in `$BLENDER`. Blender ships its own Python and numpy,
  so nothing else is needed.

## Building

```bash
npm run models                 # all monuments → public/models/*.glb
npm run models -- taj_mahal    # one monument
```

Taj Mahal V2: the editable .blend, all studio renders and the GLB:

```bash
"C:/Program Files/Blender Foundation/Blender 4.5/blender.exe" -b --factory-startup \
  -P blender/monuments/taj_mahal.py -- --renders blender/out/renders_v2 --samples 64 --res 1920
```

Garden setting renders (no export, no .blend):

```bash
"C:/Program Files/Blender Foundation/Blender 4.5/blender.exe" -b --factory-startup \
  -P blender/monuments/taj_mahal.py -- --setting garden --no-export --blend "" \
  --cameras hero,front --renders blender/out/renders_v2
```

| Flag | Default | Meaning |
|------|---------|---------|
| `--out` | `public/models/taj-mahal.glb` | GLB path (monument only) |
| `--blend` | `blender/out/Taj_Mahal_V2.blend` | editable scene; `""` skips it |
| `--renders DIR` | off | render the cameras into DIR as `taj_<setting>_<camera>.png` |
| `--setting` | `studio` | `studio` (charcoal turntable) or `garden` |
| `--cameras a,b` | all | subset of cameras to render |
| `--samples`, `--res` | 64, 1920 | EEVEE samples, image width (16:9) |
| `--no-env` | off | skip both presentation settings |
| `--no-export` | off | skip the GLB |
| `--retex` | off | regenerate the cached textures |

V1 is archived, not overwritten: `out/Taj_Mahal_High_Detail.blend`, plus
`out/v1/` (scripts, renders, GLB).

Cameras: `front`, `hero` (three-quarter), `side`, `rear`, `elevated`, `dome`,

## Motif and material library

Each motif in `lib/motifs.py` reproduces a *type* of ornament from the
reference photographs, not a copy of any specific panel. The palette is
black stems, dark-green leaves, carnelian, agate and yellow, on warm white
marble.

| Material | Motif | Used on |
|----------|-------|---------|
| `pietra_dura_arabesque` | wavy black vine, spiral tendrils, rosettes, tulips, leaves, buds | arch spandrels |
| `inlay_border` | mirrored carnelian S-scrolls with tulips between fillets | parapets, plinth, drum, chhatri friezes |
| `inlay_rosette` | black lozenges with four-petal cross flowers | foot of the main dome |
| `inlay_arcade` | small cusped arcade with hanging tulips | drum frieze, minaret bands |
| `inlay_chevron` | black-and-white zig-zag | guldasta shafts |
| `rope_moulding` | twisted black-and-white rope | drum, lotus cap, minarets |
| `railing_panel` | double black frame | balcony parapets, alcove balustrades |
| `marble_slab` / `marble_ashlar` / `marble_minaret` | coursed blocks of random length; each block has its own tone, warmth and vein layer | walls and plinth / domes and drum / minaret shafts |
| `marble` | plain warm marble with fine bump (renders only) | mouldings and details |
| `calligraphy_band` | neutral dark scroll, deliberately **not** lettering | iwan frames |

## Assumptions (architectural reference sheet)

Dimensions are approximate. They come from commonly published figures,
cross-checked against reference photographs by measuring proportions. This is
**not** a survey-accurate reconstruction.

| Element | Value used | Basis |
|---------|-----------|-------|
| Plinth | 95 × 95 m, 6.7 m high, octagonal corner bastions | published figure; bastions from photos |
| Mausoleum | 56.6 m square, 8 m chamfers | published ~57 m; chamfer from photos |
| Wall height (plinth → roof) | 22.5 m | façade width : pishtaq height ≈ 2.3–2.4 in frontal photos |
| Pishtaq | 21 m wide, 25.5 m above plinth | photo proportion |
| Great iwan | 13 m wide, spring 11 m, 5.5 m deep, half-octagonal | photo proportion; depth assumed |
| Drum | r 11.8 m, 9 m high | dome overhang ratio from photos |
| Dome | max r 13.9 m (at ~30% of its height), 22.9 m high + lotus cap | photo proportion |
| Total height to finial tip | ≈ 72 m above ground | published ~73 m |
| Roof chhatris | at (±16, ±16) m, dome r ≈ 4.2 m | photo proportion |
| Minarets | ≈ 41 m above plinth, balconies at 11 / 21.5 / 32 m, shaft r 2.85 → 2.2 m | published ~40 m; ratios from photos |
| Minaret lean | **omitted** (the real minarets lean slightly outwards) | simplification |

## V2 report

**The ten defects found in V1, and what changed**

1. **Minaret balconies** were box corbels with stick railings. They now have a
   concave cove, carved brackets with pendant buds, arched panels, a beaded
   slab, a panelled parapet with knob posts, an inlay band, a rope moulding and
   a door.
2. **Chhatris and minaret kiosks** had plain arches and flat eaves. They now
   have cusped arches cut through, colonettes, a floral frieze, and a sloping
   chhajja on brackets.
3. **Guldastas** were plain octagons. They now have chevron inlay shafts, lotus
   capitals and cupolas.
4. **The drum** had one generic band. It now has a scroll band, two rope
   mouldings and a blind arcade, with a rosette band at the foot of the dome.
   The scalloped crown is removed.
5. **The dome** profile was rebuilt: widest low, with a long taper. The lotus
   cap has deeper flutes, flared tips and rope rings, and the finial bulbs are
   fluted.
6. **Ornament** was one cartoonish trellis everywhere. It's now a library of
   seven motifs in the real stone palette, each placed where the references
   show that ornament type.
7. **Marble** was uniform, with brick-regular joints. It now uses coursed
   blocks of random length, each with its own tone and veining, at a scale set
   per element (slab walls, ashlar dome, minaret courses).
8. **The platform** had 23 identical niches per side. It now has bastions, a
   central portal group, framed bays with inlay lines, pilasters, a two-tier
   base and a border band.
9. **Façade depth:** arches have a stepped inner order, frame lines are
   thinner, and the upper alcoves have balustrades.
10. **Presentation:** a studio turntable (charcoal backdrop with sky lighting)
    is the default setting, with the garden kept as a separate one. Contact
    shadows are stronger.

Also fixed: lathe rings were not watertight. Closed profiles now loop back to
their first ring.

**Limitations and remaining defects**

- **No real calligraphy** (see the materials table). The iwan ceilings are
  faceted slopes, not muqarnas semi-domes.
- **Ornament is texture-based**, with no normal maps, so carved relief (dado
  flower panels, bracket scrolls) doesn't catch low-angle light. The minaret
  brackets are simple blocks with buds, not carved scrolls.
- **Dome block joints** are slightly too regular and contrasty at middle
  distance.
- **The studio floor** reads as a separate grey plane with a visible horizon,
  instead of fading seamlessly into the backdrop.
- **The garden setting** is still simplified: the mosque and jawab are blocks
  with domes, and the great gate isn't modelled.
- **Open edges:** the inlay bands and the chevron sleeve are thin overlays on
  solid cores, so they have open edges where they meet (hidden). The kiosk
  arcade boolean leaves small open edges.
- **Size for mobile AR:** about 265k triangles (2.2 MB) is fine on current
  phones, but a lighter variant could drop the posts, brackets and panels.
- **Interior** (cenotaphs, screen, inner dome) and the minaret lean are not
  modelled.

# Konark Sun Temple

`monuments/konark.py` → `public/models/konark.glb` (about 103k triangles,
790 KB, 4 materials). The full build also saves
`out/Konark_Sun_Temple.blend` and the renders:

```bash
"C:/Program Files/Blender Foundation/Blender 4.5/blender.exe" -b --factory-startup   -P blender/monuments/konark.py -- --renders blender/out/renders_konark
```

Cameras: `hero`, `front` (from the east), `side`, `elevated`, `tower`,
`wheel`, `horses`, `mandapa`. In the viewer and AR it's shown at
`displayScale` 0.009 (1.06 × 0.37 × 0.49 m). +X is east, the direction the
chariot faces.

| Collection | Contents |
|------------|----------|
| `Konark_Pitha` | chariot platform (jagamohana square + narrower deul square), moulded base, carved body, cornice; **24 wheels** (8 thick + 8 thin spokes, spoke medallions, hub, rim moulding) spaced around the stairs; east, north and south staircases with sloping side walls |
| `Konark_Jagamohana` | pancharatha walls (pabhaga mouldings, two carved jangha registers, bandhana, baranda); three projecting doorframes, stone-filled as today; **pidha roof** of 6 + 5 + 4 sloped slabs on recessed cores, two terraces of standing figures; crown with beki (neck), ghanta (bell), ribbed amalaka and kalasha |
| `Konark_Deul` | ruined sanctuary base: mouldings, carved wall broken open by separate boolean cuts, hollow sanctum; Surya shrines on the N, S and W faces with green-chlorite figures |
| `Konark_Mandapa` | natya mandapa (dance hall) to the east: pancharatha platform, east and west stairs, 16 pillars on a 4 × 4 grid, some broken, intact ones with bracket capitals; no roof |
| `Konark_Horses` | seven stylised harnessed horses (spline-swept tubes: barrel, arched neck with mane, head, ears, legs, hooves, tail, caparison band) flanking the east stairs |

Materials (`lib/motifs.py`): `khondalite` (coursed blocks with rain streaks
and patchy weathering), `khondalite_carved` (embossed registers of figure
niches and rosette medallions), `khondalite_weathered`, `green_chlorite`.
The carving texture evokes the density of Konark's friezes; it doesn't copy
any panel.

## Konark assumptions

| Element | Value used | Basis |
|---------|-----------|-------|
| Orientation | chariot faces east | published |
| Jagamohana | walls 28 m square + projections, about 41.5 m to the kalasha | published ~39 m surviving height (crown slightly taller here) |
| Platform | 4.5 m high; jagamohana part 42 m square, deul part 34 m | photo proportion |
| Wheels | 24, about 3 m across, 8 major + 8 minor spokes | published (≈ 9 ft 9 in) |
| Horses | seven, at the east stairs (four north, three south) | published count; placement simplified |
| Deul | collapsed; base walls about 9 m, broken | ruin state approximated |
| Natya mandapa | 20 m square platform, 4 m high, about 10 m east of the stairs | photo proportion |

## Konark limitations

- **Horses** are stylised: the real ones rear, wear rich ornament, and some
  trample figures.
- **Carving is a texture.** There are no sculpted figures except the
  abstracted terrace and shrine statues. The erotic and narrative panels are
  not modelled.
- **Not modelled:** the gajasimha (lion on elephant) guardians at the mandapa
  stairs, the Mayadevi temple, the bhoga mandapa, and the enclosure wall.
- **Roof cores** show as dark vertical slots at the ratha steps between the
  pidha slabs.

## Third-party models and scans (`blender/scans/`)

`build_scans.py` turns downloaded glTF models into web GLBs: it drops the
duplicate primitives that captured files carry, stands them upright, binds
textures (the Taj Mahal capture ships 19 maps with no assignments — see
`TAJ_MATERIALS`), welds and decimates to a web budget, scales to metres and
exports Draco GLBs with resized JPEG textures.

```bash
blender -b --python blender/scans/build_scans.py -- <name> <source.gltf> public/models/<name>-scan.glb <preview.png>
```

`<name>` is a key of `MODELS` (`taj-mahal`, `hampi`, `ajanta`, `ellora`, `red-fort`).
The Red Fort source ships flat colours only; the script replaces them with
red sandstone, marble, paving, lawn and flag textures from `blender/lib/textures.py`
(see `RED_FORT_MATERIALS`) and box-maps them at real-world scale.
Source files stay outside the repo. The site labels every model "Prepared in
Blender by Virasat"; the model authors asked not to be credited by name.
